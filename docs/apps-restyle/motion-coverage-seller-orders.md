# Motion coverage: seller orders and tracking

- **/orders**: ButtonLink (u28 sweep) on "New order" and ghost "CSV import" / "N pending" in the page header. KpiCard glow on four cards. The three counts ("Total orders", "Being processed", "On the road", "Delivered") roll up once on first load (odometer). The money in each card's foot is the unchanged `<Money>`. Filter bar (u04) with u33 TextField search (floating label, submit magnifier as the trail), u05 native Selects (placed when, store, status) and u33 DateFields for a custom range. Reset replaces "Clear". Liquid-bead Tabs (u09) for the status chips with counts. Skeleton rows while loading. u27 empty state (the "New order" action when nothing is filtered). Data table u07 with row hover lift only (no per-row animation) and StatusChip (icon + word). u16 Pagination with per-page.
- **/orders/pending**: KpiCard glow and odometer counts on three cards. Each staged row is a section card of u33 TextFields (error under the field). "Import as order" / "Import anyway" is a rolling-label AsyncButton (busy while the real import runs) that opens a ConfirmDialog restating the row first. "Save without importing" is a rolling-label AsyncButton wired to the real PATCH (Saving… → Saved / failed). "Discard" opens a destructive ConfirmDialog (busy, locked while it runs). Toasts (u32) for "Row N updated" and "Row N is now an order". Skeleton rows while loading. Positive u27 empty state "Nothing waiting" with one next step (Upload a CSV).
- **/orders/new**: u34 Stepper in sections mode, sticky, as a progress header over the same single form. The connector fills as sections pass, the section in view glows, and a click scrolls to it. Nothing is hidden or unmounted. u33 TextFields and TextArea with floating labels. The seller code and +91 are fixed lead chips. The PIN notice is a warning line. Payment mode is u10 ChoiceCards. The short-stock tick is the u03 Checkbox. "Save as draft" and "Submit for confirmation" are controlled rolling-label AsyncButtons (Saving… / Submitting…) wired to the real create and submit. **No van drive-off**: success navigates to the new order immediately, so a storytelling animation would either be cut off or delay the navigation. "Submit for confirmation" opens a ConfirmDialog first (recipient, amount to collect, consequence). The duplicate-order dialog (Dialog scale + fade) has a Checkbox acknowledgement and a rolling-label "Place it anyway". The customer-history card is static. Toasts for fill, draft saved and submitted. The sticky submit bar is solid, with no backdrop blur.
- **/orders/[id]/edit**: the same u34 sections Stepper and u33 fields. Payment mode is ChoiceCards. The COD "Use ₹…" shortcut is under the field. "Save changes" and "Save + submit" are controlled rolling-label AsyncButtons. "Save + submit" opens a ConfirmDialog (order number, amount to collect, consequence). "Discard draft" opens a destructive ConfirmDialog, replacing the inline armed confirm. Skeleton while loading. Toasts unchanged.
- **/orders/[id]**: u17 Timeline as the order tracker. The connector fills once on mount, done stages get checks, the current stage pulses (paused off-screen), each stage has a time chip, and the header shows the order number and a StatusChip. The Parcel facts and the Full history keep the shared renderers inside section cards. KpiCard glow on four cards; the line count rolls up. Header actions are u28 Buttons. Reattempt pending/refused notices are tinted info rows with icons. Items are in the data table (hover only). Charges use the data table with the unchanged `<Money>` and total. Invoice: "Generate now" is a rolling-label AsyncButton behind a ConfirmDialog restating the order number. Delivery trouble: call attempts and asks are friendly cards (icon, outcome, time, what the customer said) with StatusChips. The "What should we do?" Dialog has a u05 Select, a u33 TextArea and a rolling-label send. "Send it back now" adds a destructive ConfirmDialog restating the order number. Issues raised use u21 ListRows with a StatusChip and age, plus a u27 empty state. The customer-details editor has u33 fields, a rolling-label "Send to the courier" and a ConfirmDialog restating the order number and each field's before → after. Cancel, return, call-again and store-dispute dialogs are all Dialog (scale + fade, bottom sheet under 640px, locked while busy) with rolling-label AsyncButtons. Toasts for every result.
- **/orders/import**: u15 DropZone for the CSV (lifts and tints on drag). "Download template" and "Upload and check" are rolling-label AsyncButtons. "Import N rows" is a controlled rolling-label AsyncButton. A **ParachuteProgress** line appears for the newest run once it is seen running. Its fill is the real rows handled ÷ rows in the file; it has no number while queued and no number for a catalogue import. It lands on "Import finished" or "Import stopped". The recent-imports table shows StatusChips (the running status pulses). Skeleton rows while loading, then a u27 empty state. Toast "Import queued…".
- **/orders/import/[id]**: **ParachuteProgress** for the run, from the same record the tiles read. It polls while running and lands when done. KpiCard glow and odometer on the four counts. The status is a StatusChip in the header. "Error report CSV" is a rolling-label AsyncButton wired to the real download (Downloading… → Downloaded / Download failed). The loading skeleton is shaped like the page.
- **/tracking**: KpiCard glow and odometer on three cards (only unfiltered). There is a u33 search field. Liquid-bead Tabs for the six filters. Data table rows are hover-only. The expanded row is marked `selected`. The "History" / "Hide" control turns its chevron. The expanded parcel history is the **u17 Timeline**, the same one the public page draws. Scans run oldest first to the latest as the current step (pulsing; not pulsing once delivered). Failed and returning scans are recoloured. Earlier scans fold behind "Show N earlier scans" on a long journey. A failed attempt is a saffron inset card. Skeleton while loading. u27 empty state when there are no scans.

Reduced motion: every pattern above is handled by the global collapse in `brand/app.css`. The end states are correct with no motion: the filled connector, the checks, the final counts, the landed parachute and the rolled label.
